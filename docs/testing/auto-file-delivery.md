# 完成后自动投递附件

默认仍为点击获取。本功能是项目级选择加入的发布策略，独立于 agent 的沙箱权限。

在机器人自己的 `projects.json` 对应项目记录内添加：

```json
"fileDelivery": {
  "mode": "auto",
  "directories": ["outputs", "交付文档"]
}
```

`directories` 仅接受项目内的相对子目录；不接受项目根目录、绝对目录和越界目录。
目录联接或符号链接的真实路径也必须留在当前项目内。此配置不会改变模型、网络或沙箱。
设置 `mode: "manual"` 或删除 `fileDelivery` 可恢复点击发送。当前先提供配置项，不新增管理页面。

只有收到成功完成事件、最终结果卡片更新成功后才触发。普通任务和 `/goal` 的成功轮次均适用。
流式输出、被引导拆分的旧卡片、失败、中断、超时和没有完成事件的轮次不自动发送。
只处理本轮最终回复明确引用的文件；不遍历目录、不补发历史任务、不发送图片引用。
保留既有每轮最多 10 处文件入口、单文件 30 MB 限制。

附件由当前机器人的通道回复到本轮结果卡片，保留当前群和话题规则。发送前重新检查群绑定、
任务发起人的当前项目权限、发布目录真实路径及文件快照；上传完成后再检查权限和目录。
同一张卡片的同一文件只发送一次，自动投递与人工点击共享锁、持久化记录和回复 UUID。
上传失败会保留点击重试入口；人工重试仍限任务发起人或 Bridge 管理员。
自动发送成功后，群成员可直接使用附件消息，无需触发 Bridge 的获取回调；飞书自身的
群策略、文件策略仍然适用。

## 验证

`npm test` 覆盖真实临时文件、普通任务和 goal 的结束流程；仅模拟飞书网络端点及 agent。
包括手动默认、重复/别名、失败重试、重启不重放、群/项目/发起人绑定、全访问模式下的
发布目录越界、Windows 目录联接、上传期间撤销策略等场景。

真实群验收：用目标机器人生成一个无业务数据的测试文件，最终回复引用允许目录内的路径。
检查最终卡片后出现附件消息，普通群成员无需点击领取入口；重复点击不得再发送附件。
