# 本地文件入口

Bridge 将最终回答中的本地文件引用原地替换为蓝色交互文字。首次点击上传 IM 资源并发送文件附件；发送成功后再次点击定位附件消息。相同文件的多处引用共用发送记录，状态保存在各机器人的 `outbound-files/` 目录中，重启后继续生效。

回答完成时只检查文件元数据，不上传文件、不启动新一轮 agent，也不导入云盘文档。

## 识别规则

| 格式 | 示例 |
| --- | --- |
| Markdown 本地链接 | `[报告](./报告.pdf)`、`[报告](</目录/含 空格.pdf>)` |
| 反引号路径或文件名 | `` `/目录/报告.pdf` ``、`` `./报告.pdf` ``、`` `含 空格.txt` `` |
| 裸绝对路径 | `/目录/报告.pdf`；含空格时需用反引号或 Markdown 尖括号链接 |
| Codex 文件引用 | `codex-file-citation` 的 `path` 属性 |

相对路径以当前项目目录为基准；支持 `file://`、URL 编码以及 `:行号`、`#L行号` 后缀。只识别最终回答，不扫描项目目录或工具输出。

- 文件必须存在，且为大于 0、不超过 30 MB 的普通文件。扩展名不限；预览能力由飞书客户端决定。
- 普通权限下，解析符号链接后的真实路径必须在项目内；点击时重新检查权限和文件是否变化。
- 每张回答最多 10 处入口，重复引用也计数。复杂布局超过组件预算时，其余引用保留为可读文本。
- 目录、HTTP 链接、代码块和单独发送的 `feishu-card` 围栏不提供该入口。`![图片](路径)` 沿用图片展示流程。

普通 Markdown 链接不能触发卡片回调，因此入口使用无边框交互容器。原文件名/路径、前后文字和顺序保留，不附加文末文件区；长句换行可能略有不同。含入口的表格使用原位置分栏网格，保留行列顺序。

## 手工验收

在当前代码目录构建并启动配置好的测试机器人，同一机器人只运行一个实例：

```sh
npm run build
npm start -- --bot <机器人配置名>
```

机器人需订阅 `card.action.trigger`，并具有读取消息、发送消息及 `im:resource` 权限。

在绑定的项目目录准备普通文件、含空格文件名和 ZIP 文件，让 agent 在正常回复中分别用 Markdown 链接、反引号路径和裸绝对路径引用它们。再测试同一文件出现两次，以及文件引用位于列表、句中和表格的情况。

| 操作 | 预期 |
| --- | --- |
| 收到回答 | 文件引用原地变蓝，尚未上传附件 |
| 首次点击 | 入口暂时禁用，当前会话或话题收到真实附件 |
| 发送期间连点 | 同一文件只发送一次；同一卡片内不同文件串行处理 |
| 成功后点击任一同文件入口 | 定位已发送消息，不再上传或发送 |
| 重启后点击 | 保留发送结果；中断的入口恢复为可重试状态 |
| 文件被替换、修改或删除 | 提示原因，不发送改变后的内容 |
| 撤销权限、非发起人/管理员或转发卡片 | 拒绝获取本地文件 |
| 上传或发送失败 | 提示错误并允许重试，复用已上传资源 |
| 发送响应丢失 | 去重窗口内复用消息 UUID；超过 55 分钟拒绝自动重发 |
| 卡片更新失败 | 已发送结果仍落盘，后续点击不重复发送；重启尝试恢复入口 |

消息定位使用 IM 返回的 `message_position` 生成 AppLink；若位置不可用则打开原会话。用户在附件消息中进入飞书原生预览或下载。

## 自动验证

```sh
npm run typecheck
npm test
npm run build
```

核心回归位于 `test/outbound-files.test.ts`、`test/inline-files.test.ts` 和 `test/run-card-stream.test.ts`，覆盖路径识别、原位置布局、权限和文件变化检查、重复点击、持久化恢复及卡片刷新竞争。
