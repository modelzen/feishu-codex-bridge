# 运行卡样式与 steer 分卡

## 来源和范围

展示层参考 `vonvon-dsh` 的 `packages/feishu-adapter/src/run-card-projection.ts`、`tool-presentation.ts` 和 `card-primitives.ts`（检查版本 `b9faaf5`）：

- 灰色常规字号的过程标题、语义线条图标和统一间距。命令使用源项目内嵌的终端 PNG，各机器人首次使用时上传到飞书并缓存自己的图片 key；上传失败或超过 3 秒时使用原生图标，后续卡片刷新在一分钟后重试。无需用户机器上的图片路径。
- 思考摘要、进度文字、工具按首次出现顺序排列，最终快照更新原位置。连续工具分组，单项详情可展开。
- 工具标题显示简短动作。完整命令只在展开详情中显示一次，参数、后端已提供的输出和退出码分区显示。相同工具 ID 的重发事件更新原条目；不同 ID 的实际执行分别保留。
- 运行中计时，终态冻结用时。底部状态使用与工具行一致的飞书线条图标，不使用彩色表情。
- 运行中的停止操作使用飞书原生中号蓝底按钮和白色 `stop-record_filled` 图标。单独显示时只保留图标；与完成提醒或结束目标并列时显示“停止”。按钮形状由飞书客户端决定，不模拟圆形。排队取消使用灰色 `close_outlined` 图标和“取消排队”文字。

源仓库的 `raw-message-ingress.spec.ts` 明确测试 steer 不创建第二张卡片。因此下面的分卡行为是本次新增，源仓库没有现成实现可直接移植。

## 展开运行过程

过程直接保留在运行卡的原生折叠区域中，不创建独立查看卡，也不增加翻页按钮。操作标题不重复显示命令。展开详情后，每条完整命令只显示一次。

常规详情保留工具输出的前 1200 个字符，并标明原始长度。卡片接近飞书的字节或组件上限时，渲染器先移除工具输出，把操作和完整命令压缩到原生折叠组中。只有操作本身也无法装入单卡时，才按时间顺序保留前缀并显示明确的省略数量。渲染器不会截断已显示的命令。

## steer 行为

模型输出 A 时收到补充 B，后端确认 steer 接收后，新卡回复 B，旧卡收起并标注“已接收补充，后续输出见下一张卡片”。后续流式输出和本轮最终结果进入新卡；不会重新调用 `runStreamed`，也不会重复投递 B。

接受确认与后端事件在同一队列里按到达顺序处理。建卡期间的事件会保留；同一文本或思考 item 的最终快照扣除已展示的前缀。后端若重写了前缀，则保留完整修订文本。分卡时仍在执行的工具延续到新卡，完成的工具留在旧卡。

新卡继续使用原 turn 的终止权限和完成提醒状态。语音转写放到对应补充消息的新卡；原卡的图片和文件入口保留。

边界：

- 以 bridge 收到接受确认的时刻为展示分界，不能保证每个文本 token 在语义上只回答某条用户消息。
- 已结束 turn 的迟到确认不创建空运行卡，也不修改后续 turn；语音元数据仍归属原 turn。
- 新卡创建失败时提示用户并继续原卡，不重投已经接收的消息。
- 明确拒绝仍走原有排队/下一轮路径；接收状态不明时提示核对结果，不自动重投。
- 队列模式、不支持 steer 的后端，以及 `/goal` 运行中的消息策略保持各自既有语义。

## 验证

自动化覆盖时间顺序、重复工具事件原位更新、完整命令单次展示、大输出下的命令保留、极端容量下的明确省略提示、标准状态图标、终端图标上传失败、计时冻结，以及普通 turn、steer、goal 和现有队列竞态。

运行 `npm run typecheck`、`npm test`、`npm run build` 和 `git diff --check`。

真实飞书客户端待验收：启动包含本次改动的测试服务，发送能持续输出的任务；确认单独的停止操作显示为蓝底白色停止图标，与提醒或结束目标并列时显示“停止”，排队取消显示灰色关闭图标和“取消排队”。看到卡片后发送两条补充，确认每条被接收的补充都产生新卡、旧卡停止追加、新卡停止按钮有效。再检查终端图标、底部标准线条图标、静默工具计时和折叠详情。让任务产生四条命令和大段输出，确认没有独立查看按钮，展开过程后四条完整命令各显示一次。自动化测试使用受控后端和传输 mock，不代表已完成真实飞书或模型服务验收。
