# 飞书语音消息

项目群中符合现有响应条件的语音消息会先通过飞书语音识别转写，然后进入原会话的消息队列。模型收到的正文包含固定前缀：

```text
语音消息：请检查今天的生产报表。
```

- 保留发送人、原消息及话题的路由信息。空闲会话直接开始；正在运行时排队，即使全局设置为“引导”也不把语音插入当前运行。
- 同会话转写期间，后续消息按接收顺序等待。其他话题不受影响。
- 清空或切换会话会取消尚在准备的旧语音及其后续等待消息；项目权限变更会取消该群的准备队列并提示重发。转写完成后还会重新核验访问权限和项目设置，避免使用旧权限执行。
- 沿用项目访问控制、免 @、话题和重复消息过滤规则。私聊管理菜单及引用历史语音不在本功能范围内。
- 失败、无识别文字或超时不提交音频占位符或半段转写作为指令；给出失败提示，后续消息可继续处理。
- 依赖运行桥的 PATH 中可执行的 `ffmpeg`，以及当前机器人应用的消息资源访问和飞书语音识别权限。不使用 lark-cli 的用户登录态。
- 音频经内存管道转成 16 kHz 单声道 PCM，不在磁盘保存原音频。单条最多 16 MB / 5 分钟，总转写期限 120 秒。超过 55 秒按顺序分段调用；分段边界可能影响个别词语的识别。

接口依据：[飞书语音文件识别](https://open.feishu.cn/document/server-docs/ai/speech_to_text-v1/file_recognize)。每次文件识别不超过 60 秒；`file_id` 为 16 位字母数字/下划线。

## 验证

```sh
npx vitest run test/voice.test.ts test/voice-queue.test.ts
npm run typecheck
npm run build
```

macOS 可显式执行真实接口测试（使用当前 bot 的凭据和系统 Tingting 合成语音，不发送群消息）：

```sh
FEISHU_VOICE_LIVE=1 npx vitest run test/voice-live.test.ts
```

真实接口测试覆盖机器人身份、音频解码和 ASR 结果。飞书消息下载及模型排队另由模拟消息集成测试覆盖；不等同于真实群语音端到端验收。
